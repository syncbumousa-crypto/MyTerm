# الحسابات وبيانات المستخدمين في المواقع الثابتة

## لماذا لا تُخزَّن البيانات في مستودع الكود

| | |
|---|---|
| **الكشف** | المستودع العامّ يقرؤه كل أحد، وتُفهرسه محركات البحث |
| **لا طريق للكتابة** | الصفحة تعمل في متصفّح الزائر ولا تملك صلاحية على المستودع، فلا تصل بيانات التسجيل إليه |
| **Git ليس قاعدة بيانات** | لا بحث ولا استعلام ولا كتابة متزامنة |

## حدود الاستضافة الثابتة

تُقدّم الملفات ولا تُشغّلها. فـ JavaScript يعمل لأنه يُنفَّذ في متصفّح الزائر، وما يحتاج الخادم لا يعمل.

| يعمل | لا يعمل |
|---|---|
| أزرار، ونماذج، وحفظ في المتصفّح | قاعدة بيانات، وحسابات، وإرسال بريد |

## الحل: خدمة وسيطة

الصفحة تبقى ثابتة، وتتحدث بـ JavaScript مع خدمة تحمل الحسابات والبيانات عبر HTTPS. فلا سيرفر يُدار، ولا بيانات في المستودع، ولا تغيير للمستضيف.

| الخدمة | ما تعطي |
|---|---|
| **Supabase** | حسابات + قاعدة بيانات Postgres + صلاحيات |
| **Firebase** | حسابات + قاعدة بيانات، من Google |
| **Clerk** | حسابات فقط، بلا قاعدة بيانات |

## أمان المفاتيح

| | |
|---|---|
| `anon public` | ✅ في الكود، سليم بتصميمه |
| `service_role` | ❌ لا يدخل مستودعًا عامًّا |

**الأمان في قواعد الصلاحيات** — Row Level Security — لا في إخفاء المفتاح العامّ. ولو غابت لم يحمِ المفتاح شيئًا.

**وكلمات السر بصمة مشفَّرة لا نصّ،** ولهذا تُستعمل خدمة جاهزة لا كتابة الحسابات يدويًّا.

## ما يلزم للتنفيذ

ملف `.js` للاتصال والمعالجة · صفحتا تسجيل ودخول · حساب على الخدمة ومنه `Project URL` و `anon public key` · قواعد صلاحيات قبل إدخال أي بيانات حقيقية.
