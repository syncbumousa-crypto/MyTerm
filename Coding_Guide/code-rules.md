# قواعد بناء الأكواد والملفات

---

## 1) تعليق قبل كل كتلة

**قبل كل كتلة في أي ملف، يُكتب تعليق يذكر ثلاثة، كلٌّ منها برمزه:**

| الرمز | الحقل | ماذا يحمل |
|---|---|---|
| 🔤 | **اللغة** | اسم لغة الكتلة، يأتي بعد الرمز مباشرة بلا فاصل |
| 🎯 | **الهدف** | ماذا تفعل، ولماذا هي موجودة |
| 🔗 | **الارتباط** | كيف تتصل بالكتلة التي قبلها، أو بالتي تليها |

**ولماذا رمز لا كلمة:** الرمز يُميَّز بلمحة بصر، ويُقرأ بلا ترجمة. وثلاثة رموز مختلفة الشكل تُفرّق الحقول أسرع من ثلاث كلمات متشابهة الطول.

---

## 2) لغة التعليق: الإنجليزية، بمفردات بسيطة

**التعليق في الكود يُكتب بالإنجليزية**، بكلمات دارجة شائعة وتركيب سهل.

| | |
|---|---|
| ✅ | كلمات شائعة، وجمل قصيرة، ومضارع بسيط |
| ✅ | `shows`, `goes in here`, `does nothing`, `is ready`, `fills the screen` |
| ❌ | مصطلحات ثقيلة، ومبنيّ للمجهول ملتوٍ، وجمل متفرّعة طويلة |

**ولماذا الإنجليزية:**

1. **الاتجاه.** الكود كله إنجليزي يُقرأ من اليسار. فالتعليق بالعربية كان يخلط اتجاهين في سطر واحد فيتشابك عرضه على GitHub. وبالإنجليزية يستقر السطر على اتجاه واحد.
2. **لا ترجمة.** أسماء الوسوم والخصائص إنجليزية أصلًا — `head` و `body` و `margin` — فالحديث عنها بالإنجليزية مباشر بلا التواء.

> **وهذا الملف و WorkCulture يبقيان بالعربية.** القاعدة للتعليق **داخل الكود** وحده، لا لمراجعي.

**ومفردات بسيطة** لا تعني ناقصة: الجملة تشرح الهدف والارتباط كاملين، لكن بأبسط كلمة تؤدي المعنى.

---

## 3) صيغة الكتابة

**حقل في كل سطر، داخل إطار يفصل الكتلة عمّا قبلها:**

```html
<!-- ============================================================ -->
<!-- # 🔤 HTML -->
<!-- # 🎯 Letter encoding, so Arabic text shows the right way -->
<!-- # 🔗 Comes before any Arabic in the file, or the letters break -->
<!-- ============================================================ -->
<meta charset="utf-8">
```

وفي CSS الصيغة نفسها بعلامتها:

```css
/* ============================================================ */
/* # 🔤 CSS */
/* # 🎯 ... */
/* # 🔗 ... */
/* ============================================================ */
```

**وإذا طال الشرح** فيُكمَل في سطر تالٍ يبدأ بـ `#` وحدها، بإزاحة تحت النص:

```css
/* # 🎯 First line of the explanation, */
/* #    and it goes on here */
```

### تنبيه في HTML

الإطار بعلامة `=` لا `-`. **وشرطتان متتاليتان `--` داخل تعليق HTML تكسرانه**، فلا تُستعملان في النص ولا في الإطار.

### ولماذا سطر لكل حقل

- كل حقل يُعرف بموضعه فلا يحتاج قراءة السطر كله.
- الأسطر تبقى قصيرة فلا تمرير أفقي على GitHub.
- والإطار في سطرين مستقلّين فلا يزاحم نص الشرح.

## 4) ما تُعدّ كتلة

**الكتلة مجموعة من الكود معنيّة بشيء واحد من الموقع.** ليست سطرًا، ولا وسمًا، ولا كل عنصر على حدة.

> **والمعيار:** لو شُرحت المجموعة بجملة واحدة فهي كتلة. وإن احتاج كل سطر فيها جملة، فقد نزل الشرح أدنى من المستوى المطلوب.

مثال من موقعي — **ثلاث كتل في `index.html`:**

| الكتلة | ما تضم |
|---|---|
| **تهيئة المستند** | `DOCTYPE` و `html` و `head` والوسمان `meta` و `title` |
| **استدعاء التنسيق** | وسم `link` الذي يجلب `style.css` |
| **المحتوى** | وسم `body` |

**ولا تعليق على:**

- وسوم الإغلاق مثل `</head>` و `</html>`، فهي نهايات لكتل سبقت.
- سطر واحد داخل كتلة سبق شرحها.
- وسم لا معنى له منفردًا، كـ `meta` بين إخوته في التهيئة.

**وإذا كبرت الكتلة** حتى صار فيها أجزاء ذات شأن، قُسِّمت كتلتين. والقياس **المعنى لا عدد الأسطر**.

> **وعلامة الخطأ:** إذا صار التعليق أكثر من الكود، فالتقسيم أدقّ مما يجب. هذا ما وقع أول مرة: تُسع كتل لملف كوده أربعة أسطر عاملة.

## 5) ما لا يمكن التحكّم فيه

| | |
|---|---|
| **`.md`** | يعرضه GitHub **مستندًا مُصيَّرًا**: عناوين وجداول واتجاه |
| **`.html`** | يعرضه **كودًا خامًّا**: سطورًا بخط ثابت واتجاه من اليسار |

والتعليق **سلسلة حروف يتجاهلها المُحلِّل.** فلا عناوين فيه، ولا نص عريض، ولا اتجاه، ولا تُقرأ فيه علامات Markdown: `#` حرف عادي، و `dir="rtl"` لا أثر له لأنه يخصّ صفحة تُرسم لا كودًا يُعرض.

**والتنسيق الوحيد الموجود هو اللون** من تلوين الصيغة، يصبغ GitHub به التعليقات لتُميَّز.

فالشرح المطوَّل الذي يحتاج جداول وعناوين **مكانه ملف `.md`**، لا تعليق في الكود.

---

## 6) فصل الملفات

| اللغة | مكانها |
|---|---|
| **CSS** | ملف `.css` مستقل، يُستدعى بوسم `link` في `head` |
| **JavaScript** | ملف `.js` مستقل، يُستدعى بوسم `script` قبل نهاية `body` |
| **HTML** | **لا يُفصل بوسم أصيل.** ولو احتجت رأسًا مشتركًا بين صفحات، فـ Jekyll يُدرج بـ `include` من مجلد `_includes` |

**ولا يُنشأ ملف قبل أن يكون فيه ما يُكتب.** الملف الفارغ آلة بلا موضوع، وهي نفسها القاعدة التي حُذف بها `.gitignore`.
