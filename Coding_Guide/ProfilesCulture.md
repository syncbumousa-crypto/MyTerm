# الحسابات وبيانات المستخدمين في المواقع الثابتة

---

## 1) لماذا لا تُخزَّن بيانات المستخدمين في مستودع الكود

| | |
|---|---|
| **الكشف** | المستودع العامّ يقرؤه كل أحد، وتُفهرسه محركات البحث. فبريد المستخدمين وكلمات سرهم تصير مكشوفة |
| **لا طريق للكتابة** | الصفحة تعمل في متصفّح الزائر، ولا تملك صلاحية على المستودع. فلا تصل بيانات التسجيل إليه، والملف يبقى فارغًا |
| **Git ليس قاعدة بيانات** | لا بحث، ولا استعلام، ولا كتابة متزامنة من عدة مستخدمين |

> **القاعدة:** لا يدخل المستودع العامّ ما لا يُراد كشفه. وبيانات الحسابات أول ما تُختبر فيه.

---

## 2) ما يستطيعه الموقع الثابت

الاستضافة الثابتة — GitHub Pages ونحوها — **تُقدّم الملفات ولا تُشغّلها.**

| يعمل | لا يعمل |
|---|---|
| أزرار، ونماذج، وحسابات رقمية، وحفظ في المتصفّح | قاعدة بيانات، وحسابات مستخدمين، وإرسال بريد |

و JavaScript يعمل لأنه يُنفَّذ في متصفّح الزائر. وما يحتاج تنفيذًا على الخادم لا يعمل.

---

## 3) الحل: خدمة وسيطة

الصفحة تبقى ثابتة، وتتحدث بـ JavaScript مع خدمة تحمل الحسابات والبيانات:

```
المستخدم يضغط «إنشاء حساب»
   └─► JavaScript يرسل البيانات إلى الخدمة عبر HTTPS
        └─► الخدمة تُنشئ الحساب وتخزّنه عندها
             └─► تُعيد للصفحة رمز دخول
```

فلا سيرفر يُدار، ولا بيانات في المستودع، ولا تغيير للمستضيف.

| الخدمة | ما تعطي |
|---|---|
| **Supabase** | حسابات + قاعدة بيانات Postgres + صلاحيات. خطة مجانية تكفي مشروعًا صغيرًا |
| **Firebase** | حسابات + قاعدة بيانات، من Google. أقدم وأوسع انتشارًا |
| **Clerk** | حسابات فقط، وواجهة أجمل. لا قاعدة بيانات |

> الحدود والأرقام تتغيّر، ووثائق كل خدمة هي المرجع.

---

## 4) أمان المفاتيح

| المفتاح | أين يوضع |
|---|---|
| **`anon public`** | ✅ في الكود، وهذا سليم بتصميمه. مقيَّد بقواعد الصلاحيات |
| **`service_role`** | ❌ لا يدخل مستودعًا عامًّا أبدًا. يتجاوز كل الصلاحيات |

**والأمان في قواعد الصلاحيات لا في إخفاء المفتاح العامّ.** تُكتب في لوحة الخدمة — Row Level Security في Supabase — وتحدد من يقرأ ماذا ومن يكتب ماذا. ولو غابت لم يحمِ المفتاح شيئًا.

**وكلمات السر لا تُخزَّن نصًّا** لا في الموقع ولا عند الخدمة، بل بصمة مشفَّرة لا تُرَدّ إلى أصلها. وهذا من أسباب استعمال خدمة جاهزة لا كتابة الحسابات يدويًّا.

---

## 5) ما يلزم للتنفيذ

| | |
|---|---|
| ملف `.js` | يحمل الاتصال بالخدمة، ومعالجة التسجيل والدخول |
| صفحتان | نموذج إنشاء الحساب، ونموذج الدخول |
| حساب على الخدمة | ومنه `Project URL` و `anon public key` |
| قواعد صلاحيات | تُضبط في لوحة الخدمة قبل إدخال أي بيانات حقيقية |
